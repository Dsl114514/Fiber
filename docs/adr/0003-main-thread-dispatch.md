# 全部 Mod 回调在游戏主线程执行

线程契约定为:Runtime 把事件入队,在游戏主循环统一分发,Mod 回调永远运行在游戏主线程。选择理由:Mod 作者几乎全是业余开发者,线程安全是把最难的问题甩给用户;主线程分发让回调内可以安全调用游戏函数(本就只能在主线程做的事),事件语义可预测。

代价:主循环 hook 成为早期核心逆向任务(找到稳定的 tick/主循环函数并 hook 它作为分发点),事件从发生到回调有一帧以内延迟 —— 对聊天拦截等场景可接受。

# Considered Options
- 事件线程直接回调:实现最简,但 Mod 需自行加锁、不可安全调游戏 API,事故面大。
- 先简单后统一:alpha 阶段省事,但线程契约是 Mod 生态的根基假设,中途翻转会让所有存量 Mod 返工,契约类决策必须一次定对。

# Consequences
- 主循环特征码定位进入 M1/M2 关键路径,定位失败会阻塞事件系统落地。
- 事件对象默认带 `cancelled/consumed` 标志,主线程分发天然支持优先级与消费阻断。
- 内核内部仍可多线程(如文件 IO),但与 Mod 的边界是单线程的。
